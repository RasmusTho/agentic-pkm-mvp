# System-wide credential routes — 2026-10-18

## Principle and review boundary

A credential owner MUST bind the credential to its consumer, physical execution host, channel,
store, scope, allowed callers, handoff, and lifecycle. An agent executes an authorized task; its
model, repository, task, or machine identity alone MUST NOT grant secret access. Prefer the
server/host-local consumer boundary. Raw values MUST remain outside model context. Missing or
ambiguous ownership, authority, or binding MUST stop the affected operation. Keep existing stores;
this review authorizes no provisioning, grant, rotation, revocation, deployment, or provider call.

The normative rule lives in `docs/SECURITY.md :: System-wide credential access`. This document is a
point-in-time projection, not a new registry, external-helper inventory, or access authorization.
Rows identify logical credentials and declared mechanisms, never material or secret fingerprints.

Status vocabulary: **implementerad** = source implements the stated boundary, without proving
installation/access; **live-kvalificerad** = fresh exact target/action/identity evidence;
**väntande** = an explicit binding, access, acceptance, or review gap;
**enbart specificerad** = declaration/target only. A row's source evidence never automatically
qualifies another host, channel, credential, operation, or caller.

No BWS, provider, or application-credential access was freshly live-qualified by this audit. SSH
admission alone was qualified for the exact metadata action below. On 2026-10-18, the existing
workstation → Demerzel → channel-VM SSH relay returned `LoadState=loaded`, `ActiveState=active`,
`SubState=running` for `yggdrasil-bws-deploy@dev.service`, `@test.service`, and `@prod.service`.
Only those unit properties were requested; no environment, logs, token, or secret files were read.
This proves relay reachability and unit state only. Direct workstation SSH failed for all three
channels; the successful existing relay required no identity or grant change.

The audit read tracked code/configuration, owner docs and instructions, bounded GitHub Issue/PR
metadata, and relevant memory routing notes. Identifier-only source searches excluded secret/env
files. It did not read credential stores, private-key bytes, process environments, live logs,
private vault note bodies, or recovery material, and did not run `secrets check` or a provider call.
It makes no claim that all historical logs, notes, memory, stores, or Git history are secret-free.
