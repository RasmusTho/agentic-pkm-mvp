Scope

Design specification only. No implementation code. Governance, vault, and runtime contracts are out of scope and must be preserved.

Yggdrasil · Companion UI

A note-reading surface that is not yet calm enough to read in.

The Companion UI has the right bones for a cognitive prosthesis — a three-column shell, a vault-native note body, a governance rail, an outline. The bones are not the problem. Every surface above the bones is currently tuned for an operator inspecting a runtime, not for an architect reading their own thinking. The work ahead is mostly subtraction.

01Executive assessment

The note body is structurally primary and visually subordinate.

The UAT screenshots show a workspace whose loudest, top-most, full-width surface is a band of runtime telemetry — SERVER-SIDE RUNTIME, WRITEGUARD, CANVAS disabled, UPDATE FLOW disabled, GOVERNANCE VIA UPDATE, TRACE 8f3c… — followed by a second dense block restating artifact id, content hash, properties and tags. Only after roughly one-third of the viewport has been spent on machine state does the user reach the note title. The Panel rail on the right, meanwhile, shows five labeled idle states stacked vertically in agent-blue cards, the last of which (Reorient) renders a wall of bulleted prose. Inside this dashboard, the note body is a card with a visible inset border. The body is where the user has come to think; the UI presents it as one panel among many.

Two things follow. First, the most consequential design move is not a new component — it is reducing the visual weight of everything that is not the note until the note becomes the obvious primary surface on first glance, without the user having to choose where to look. Second, the Panel and the metadata band are conflating two different jobs: orientation ("where am I, when was this, is this fresh?") and governance state ("can I edit, what is the runtime doing, what are the proposals?"). They need to separate.

The Markdown renderer itself is in better shape than the surrounding shell. Basic constructs render. Callouts are the strongest visual in the system and should be the typographic North Star. The headings are too large, too uniform, and too closely scaled — but this is a CSS-token problem, not a renderer problem.

▍ thesis

The Companion UI is not failing as a Markdown viewer. It is failing as a cognitive surface because the chrome around the note is heavier than the note. Fix the chrome first; the renderer second. Do not redesign the architecture, do not rebuild the rails, do not collapse Panel into Canvas.

03What creates cognitive load

The user is being asked to read the runtime, not the note.

Cognitive load in this UI is generated by three patterns: machine state surfaced as primary content, redundant restatement of the same information across surfaces, and identifiers presented with the same visual weight as content. None of these are bugs. Each is a deliberate design decision that needs to be reversed for this audience.

3.1 The runtime telemetry band is the loudest thing on the page

The band reading SERVER-SIDE RUNTIME · RUNTIME dev / local-dev · VAULT/CHANNEL vault / dev · WRITEGUARD ok · CANVAS disabled · UPDATE FLOW disabled · GUARD degraded · WORKSPACE UPDATE disabled / active_note_body · UPDATE REASON canvas_disabled / inherited · GOVERNANCE VIA UPDATE disabled · TRACE 8f3c7b55… is a dump of runtime state at the top of every note view. The user must parse this every time they open a note, then mentally suppress it to get to the title. It is not an orientation aid; it is the contents of a debug log promoted to a header.

3.2 The metadata band is restated three times

The same artifact is described as: a path in the URL bar; a NOTE_PATH input below it; a PATH chip below the title; an ARTIFACT chip; a HASH chip; a PROPERTIES block with title, kind, review_state, trust, origin, tags and uuid; and again as TRACE 8f3c… in the runtime band. The user does not need this said six times. They need it said once, calmly, where they can find it when they want it.

3.3 The Panel rail rewards attention it cannot return

Five Panel sections are visible (Companion/Panel, Canvas, Panel, Suggestions, Find, Reorient), each in agent-blue, each saying some variant of "idle / disabled / unavailable / read-only". The Reorient block then renders a long bulleted paragraph in agent-blue body text that scrolls below the viewport. The eye is drawn there; nothing actionable is there; trust erodes a little with each glance.

3.4 Heading levels collapse onto one visual rank

H2 ("2. Outline and right rail navigation") and H3 ("2.1 First nested heading") appear at nearly identical size. The user must read the numbering ("2." vs "2.1") to know the level, defeating the purpose of having a visual hierarchy at all. Even H1 (the note title) is similar enough to the body H2s that the title's status as landmark depends on its serif face, not on size.

3.5 There is no signal that the visible state is fresh

If the user returns to the tab after lunch, nothing on the page communicates whether the note, the Panel state, the runtime state, or the outline are current as of now or as of three hours ago. The Reorient block mentions last_ingest_at=unknown, which is the opposite of reassuring. There is no "as of HH:MM" anywhere.

! cost

Each of these is small in isolation. Together they put the user into maintenance mode the instant the page loads — the cognitive posture of inspecting a system rather than thinking with it. A cognitive prosthesis cannot afford that posture as its default.

04What creates friction

Friction is structural, not cosmetic.

4.1 The note body is a card inside a dashboard

The reading column is wrapped in an inset surface with a visible border, raised against the page background. This makes the note feel like a tile in a control panel, not a writing surface. Compare to Obsidian Reading View, where the body sits directly on the page and the rails are subordinate frames around it. The current treatment subtly tells the user: "the dashboard is the surface; the note is a widget inside it." That framing fights the entire premise.

4.2 The address bar carries presentational weight

The URL ?note_path=📥+Inbox%2FCompanion_UI_Markdown_Feature_UAT.md is the user's primary way to switch notes. The emoji and percent-encoding leak from the vault into the browser chrome. This is a deeper architectural issue, but inside the design review's scope: the in-app NOTE_PATH input with LOAD / BROWSE VAULT buttons duplicates the address bar, while neither offers the equivalent of an in-vault file picker, recent notes list, or quick-open. The user is given two ways to do the same job and neither is the right one.

4.3 The outline truncates mid-word with no tooltip

"Companion UI Markdown Fea…" and "2.2.1 Another third-level …" are visible in the rail. There is no tooltip, no hover-expand, no marquee. If a heading is interesting enough to truncate, the user must scroll the body to recover the rest. The outline is a navigation surface; truncating its labels without a recovery affordance is friction by design.

4.4 Read-only state is told, not shown

The phrase "read-only" appears in PROPERTIES, in PANEL, and in REORIENT. The note body itself gives no visible indication that it is not editable — no caret-blocked cursor, no muted toolbar, no "Canvas editing unavailable" line at the top of the body. The user has to learn the rule from the rails. When body-edit lands, removing the affordance will be a hidden change.

4.5 The leaked debug string above the band

The screenshot shows Degradedvault/dev8f3c7b55433e4126b1cb3a6ae30b430c rendered as unstyled text bleeding out from above the runtime band. Whether this is a server-rendering accident or a state label that has lost its container, it reads as a broken page. A user encountering it for the first time would reasonably assume the system is in an error state. Implementation issue; flag here because the design must specify that no raw state string is ever allowed outside a labeled surface.

05Visual hierarchy

Hierarchy is currently inverted. It needs to be redrawn around the act of reading.

The right hierarchy for this surface is approximately this list, read top-to-bottom, in order of visual prominence:

  1. Note body — typography, whitespace, callouts. The unmistakable primary surface.
  2. Note title and one-line orientation — title, breadcrumb path, "as of HH:MM". A landmark and a freshness signal. Nothing else.
  3. Outline (left rail) — present, scannable, recessive. Becomes prominent only when used.
  4. Panel (right rail) — visible only when it has something to say. Otherwise a quiet column header and one collapsed strip.
  5. Properties / artifact identity — collapsed by default into a single line; expandable on demand.
  6. Runtime state — a single status pill near the title (e.g. "Canvas off · degraded") that expands to the full telemetry on click. Never a full-width band.
  7. DEV / NOT PRODUCTION — present but small. A 28-px corner ribbon, not a hero element.

The current page maps almost in reverse: runtime state, dev banner, properties and identity all sit above the title at full visual weight. The note body, the actual subject, is third or fourth in line.

Current — observedInverted
Proposed — calmedBody-first

The proposed sketch is illustrative, not pixel-binding. The key moves are: collapse the runtime band to a single status line; demote PATH/ARTIFACT/HASH into a one-line metadata strip with a properties ▾ disclosure; remove the body card border; convert the Panel from five vertical cards into a column of one-line section headers that expand only when state is non-idle.

06Markdown renderer · typography & design spec

A reading surface, not a tile in a dashboard.

All tokens reference the Yggdrasil design system at colors_and_type.css. The renderer remains server-rendered HTML; this spec is achievable through CSS and Tailwind utilities alone. No pipeline rewrite is required.

6.1 Body column

Width
max-width: 68ch (≈ 720 px at 15 px base). Body column is centered in its grid cell; no card border, no inset background.
Background
var(--bg-base) — same as page. The note body is not a panel.
Side padding
Minimum var(--space-8) (32 px) between body column and either rail. The whitespace itself is the visual divider.
Vertical padding
var(--space-10) top, var(--space-12) bottom — generous baseline so the title lands.

6.2 Heading scale

H1 remains a display landmark. H2 through H4 step down sharply. Long notes must not feel like a sequence of equally-loud headings interrupted by occasional prose.

6.3 Vertical rhythm

H1 → next block
32 px below; preceded only by the orientation line.
H2 top / bottom margin
40 px top, 12 px bottom. Underline rule: 1 px solid --border sitting tight under the heading text, 60–80 % column width.
H3 top / bottom margin
28 px top, 8 px bottom. No underline. Gold bar prefix (4 × 14 px, --accent-dim) signals depth without competing with H2.
H4 top / bottom margin
20 px top, 4 px bottom. Uppercase mono label sits flush left; reads as a section tag, not a continuation of body.
Paragraph spacing
margin-bottom: 16 px. Line height 1.65. Consecutive paragraphs visibly separate without needing rules.
List spacing
4 px between list items; 16 px before and after the list.

6.4 Inline elements

Bold
Weight 600, color --fg-1 (same as body). No color shift.
Italic
EB Garamond italic for emphasis inside body prose feels too literary. Use Space Grotesk italic, same color. Reserve display serif for headings only.
Inline code
JetBrains Mono · 0.875em · background --bg-raised · 1 px border --border · radius 2 px · padding 1 / 5 px. Visible but quiet.
External links
Color --accent (gold). Underline --accent-dim, offset 3 px. Hover: text --fg-1, underline --accent.
Resolved wikilinks
Same as external link, but with a leading "↗" or "::" glyph at --fg-3 to distinguish vault-internal navigation. Underline gold.
Unresolved wikilinks
Color --fg-2. Underline dashed, color --destructive, offset 3 px. title attribute "[[Name]] — not found in vault". Never invisible.

6.5 Block elements

Code block
Background --bg-surface, border --border, radius --radius-md (4 px), padding 16 / 18 px. Top-right corner: a small uppercase mono language label (e.g. python) in --fg-3, 11 px, 0.08em tracking. Body: JetBrains Mono 13 / 20. No syntax highlighting in v0 — adopting a highlighter is a separate decision. Inline horizontal scroll on overflow.
Blockquote
Left border 2 px --border-strong, padding-left 20 px. Body color --fg-2 (slightly muted relative to body). No background fill — a blockquote is not a callout. Italic optional via author choice.
Callouts
Preserve the current pattern exactly. Formalize as: 1 px border --border; 2 px left border in the type color; 4 px radius; padding 16 / 20 px; header row with 16 px circular glyph + uppercase type label in the type color; body in --fg-1. Eight types: note (cyan), tip (vault green), info (agent blue), question (accent gold), warning (amber), danger (destructive), success (vault green), quote (fg-2). Foldable callouts: a chevron at the right side of the header; collapsed state hides body, keeps header.
Tables
Header row: --bg-base background, mono uppercase labels 11 px / 0.08em / --fg-3, bottom border 1 px --border. Data cells: 12 / 14 px padding, body color --fg-1, dashed bottom border between rows --border. No row striping. Overflow: horizontal scroll on narrow viewports; do not wrap cells. Tables are full body width, never width-constrained narrower than the body column.
Task lists
Custom checkboxes (not native). Box 14 × 14 px, 1.5 px border --fg-3, radius 2 px, vertical-align baseline +2 px. Checked: fill --accent-dim, border --accent, check glyph in --bg-base. Read-only state: cursor default, no hover affordance. When body-edit lands: cursor pointer, hover lightens border one step. Read-only is the current truth; the design must show it.
Horizontal rule
1 px solid --border, 32 px top and bottom margin. No decorative variant.
Images
Native rendering: full body-column width, radius 4 px, no caption styling by default (a paragraph immediately following an image and beginning with italic is treated as a caption — body color --fg-2, 13 px, centered). Loading placeholder and missing-image state specified in §9.
Embeds (Mermaid, Dataview, etc.)
Failed embed treatment specified in §9. Successful embed: full body-column width, neutral border, top-right type label like a code block.

6.6 Heading anchors

Hidden by default. Visible on heading hover only — a small # glyph in --fg-3, 14 px, appearing 8 px to the left of the heading, on a 150 ms fade. Clicking copies the URL with the anchor. The glyph must not shift heading layout when it appears.

07Layout & rail recommendations

Three columns, sized to the job they do.

7.1 Column widths

Outline (left)
Fixed 220 px on desktop. Collapsible to a 36 px ribbon with a hamburger affordance on narrow viewports (< 1100 px).
Body (center)
Flexible, max-width 68 ch (~ 720 px). Centered in its grid cell. Side gutters absorb the rest of the column width up to the rails.
Panel (right)
Fixed 280 px on desktop. Hidden behind a peek tab on viewports < 1300 px; drawer behavior on narrow / mobile.

7.2 The header strip replaces the band

A single 32 px tall horizontal strip across the top, ordered left to right:

  • Wordmark — "Yggdrasil" in EB Garamond 16 px, gold-dim. Click → return to vault root.
  • Vault chip — mono "Niflheim · vault ok" with a 6 px --vault dot. Click → vault picker / browser.
  • Runtime status pill — single token: "canvas off" or "runtime degraded" or "ok". Click expands a popover with the full telemetry currently shown in the band.
  • Freshness — mono "as of 14:22". Tooltip: full timestamp + last ingest at.
  • (flex spacer)
  • Quick-open — "/" or "⌘K" affordance for switching notes. Replaces the NOTE_PATH input.
  • Browse vault — secondary button.
  • DEV ribbon — 28 px corner pill, --amber on --amber-muted, only shown in non-prod environments.

7.3 The metadata strip replaces the chips and properties block

Directly under the note title, a single line in JetBrains Mono 12 px / --fg-3:

The properties ▾ disclosure expands into the current properties table. Artifact id and content hash live inside that expanded view, not above it. Default state is collapsed.

7.4 Outline rail behavior

  • Font: Space Grotesk 13 / 18, color --fg-2 at rest, --fg-1 on hover, --accent when the current scroll position is inside that section.
  • Indentation by depth: 0 / 12 / 24 / 36 px. H4+ may be hidden by default behind an "expand outline" affordance; preserve markup so anchor links still work.
  • Truncation: single line with CSS ellipsis; title-attribute on hover; on hover the row expands to wrap, revealing the full heading.
  • Current-section indicator: a 2 px --accent bar inset on the left edge of the active row, not a background fill.
  • The outline column has its own subtle background (--bg-surface) but no border on the body side. The whitespace gutter does the separation.

08Panel / governance separation

The Panel is a quiet column with an agent voice. Not five idle cards.

The Panel must remain visually and interactionally distinguishable from the note body. That distinction is currently overspent: the Panel rail shouts in agent-blue even when it has nothing to say. The distinction needs to come from character, not from volume.

8.1 The Panel has one job per section, and most jobs are idle most of the time

Panel sections, in order: Proposals, Canvas (body-edit) status, Suggestions, Find, Reorient. Each section has two display modes:

  • Idle / null state — one line, 13 px, --fg-2. Section title in mono uppercase --fg-3, single short sentence after it. No card, no border, no agent-blue background. The Panel rail's structure persists; its volume drops to near zero.
  • Active state — a card with a 2 px --agent left border, agent-blue type label, provenance line, body, and explicit action affordances (Apply / Discard / Defer). Only active sections get a card.

8.2 Agent voice tokens

Container
Background --bg-surface, 1 px --border, 2 px left border --agent, radius 4 px.
Type label
JetBrains Mono 11 px / 0.08em / uppercase / --agent. Example: "PROPOSAL · classification".
Provenance
One line, 12 px mono, --fg-3. Example: "hugin · 2026-05-26 14:18 · confidence 0.82". Always present on agent-authored content. Never optional.
Body
Space Grotesk 13 / 20, --fg-1. May contain inline mono tokens.
Actions
Right-aligned row: Apply primary (gold), Discard secondary, Defer tertiary. Buttons sized 28 px tall, 12 px text. Apply is never the default focus — the user must intentionally claim authorship.

8.3 The Reorient block must collapse to a single line at rest

The current Reorient output is a long, scrolling, agent-blue bulleted summary. This is information that could be useful when the user explicitly asks "where am I?", and it is actively harmful when shown unsolicited. The Panel section should default to:

Reorient

Clicking recall expands the current verbose Reorient body inline. The default state is one line. The expanded state inherits the agent-blue card treatment described above.

8.4 The note body must never look like the Panel and vice versa

Tokens reserved exclusively for the Panel: agent-blue (--agent), provenance lines, the Apply / Discard / Defer action row, the 2 px left agent-blue rule. The note body must never use any of these. Tokens reserved exclusively for the note body: EB Garamond display headings; callouts as the only colored block element; full body-column width. The Panel must never use the display serif.

8.5 Canvas (body-edit) state belongs in the Panel, with a body-side echo

"Canvas editing is currently disabled by runtime configuration" should live in the Panel Canvas section as a one-liner at rest. When the user attempts an edit on the body (clicks into the prose), the body shows a 1-line read-only pill at the top right of the body column — ▍ read-only · Canvas off — that links to the Panel section. The body never shows a modal, never blocks scrolling, never displays an error toast. Disabled state should feel like a closed door, not a slammed one.

▍ rule

Every degraded state must obey three rules: (1) the note body remains readable, (2) the user can identify the failure within one second of looking at the affected element, (3) there is at most one place in the UI where the same condition is repeated.

11Codex-ready implementation guidance

Stated as design specification. Codex implements; this section does not.

11.1 What Codex should do

  • Implement category A (Quick visual fixes) first, as a single bounded PR scoped to colors_and_type.css, the Tailwind config, and the Jinja templates' class attributes. No HTML structure changes beyond adding wrapper classes where required for the spec.
  • Implement category B (Structural layout) as separate, bounded issues — one per row in the §10-B table. Each issue must reference the row by ID (see §12 UAT checklist).
  • Move all artifact metadata into a single Jinja partial that renders the breadcrumb strip + collapsible properties disclosure. The current PROPERTIES / chips templates become its inputs.
  • Build a Panel section component with a two-mode API: state="idle" | "active". Idle renders the one-line strip per §8.1; active renders the agent-card per §8.2. The Reorient block is just a Panel section with custom expanded content.
  • Extend the Tailwind config with the heading scale, line heights, and column widths in §6 and §7. Prefer custom-property bridges (colors_and_type.css) over inline arbitrary values.
  • Surface a small handful of error-state partials: renderer/failed_embed.html, renderer/missing_image.html, renderer/unresolved_link.html. Each partial is exercised by a UAT fixture note.
  • Add a build-time check: any text node rendered outside a known design-system container component is a warning. This catches future leaks like the observed Degradedvault/dev8f3c… string.

11.2 What Codex must not do

  • Do not fix Mermaid, wikilinks, images, or body edit as part of this design pass. The renderer pass owns only the degraded-state visual treatment, not the underlying functional fix. Each functional fix is a separate, bounded issue.
  • Do not merge note body and Panel. The 2-px --agent left rule lives only on Panel containers. The body never adopts agent chrome.
  • Do not hide Markdown semantics. Headings remain <h1>…<h6>, lists remain semantic, blockquotes remain blockquotes, tables remain tables. No styling decision may replace semantic markup with <div> soup.
  • Do not make task checkboxes interactive until the Canvas body-edit API is wired. The read-only treatment is the truth in v0.
  • Do not add new colors. If a state needs a hue not in colors_and_type.css, the answer is to compose existing tokens, not extend the palette.
  • Do not introduce visual regression screenshot tests as the primary verification path. Use DOM assertions and the UAT checklist below. Screenshots are evidence, not contracts.
  • Do not infer scope from this document. Each bounded issue lifts one section and lists its specific scope. Anything not lifted is not in scope.

11.3 Order of work — recommended issue sequence

  1. Token alignment — apply §6 typography + spacing + radius tokens. PR scoped to CSS only.
  2. Header strip — replace runtime band with §7.2 strip; collapse properties per §7.3. One issue.
  3. Body column — remove card; enforce max-width: 68ch; apply heading scale and rhythm. One issue.
  4. Panel state model — implement idle / active per §8. One issue covering all five sections.
  5. Outline rail polish — typography, truncation, current-section indicator. One issue.
  6. Error-state partials — unresolved link, failed embed, missing image, body-edit pill. One issue per partial; each ships with a fixture in the UAT note.
  7. Responsive collapse — apply §7.5 breakpoints. One issue.
  8. Build-time orphan-text-node warning — one issue. Catches the Degradedvault/dev8f3c… class of regressions.
▍ boundary

Codex implements from this specification and from each governing bounded issue. Where this specification is silent, Codex stops and raises a question. Codex does not infer; it does not bypass governance; it does not expand scope. Per CODEX_IMPLEMENTATION_BOUNDARY.md.
